# QQ 群 AI 对话机器人

一套可以直接跑的 QQ 群聊 AI 机器人。**双击一个 bat 文件就能用**——不用敲命令、不用手改配置文件，
启动器会打开一个网页让你填 QQ 号、模型厂商、API Key 和人设，填完自动装依赖、自动下载协议端、
自动拉起机器人，最后把扫码登录页推到你面前。

装完之后它有几个能力：

1. **对话** —— 在群里 @机器人 + 提问，它就会调用大模型回答
2. **群文件 / 群相册检索** —— 问「群里有没有 XX」，它去翻群文件，告诉你文件在哪个文件夹
3. **群精华消息检索** —— 问「精华里有没有讲 XX 的」，它说清是哪位群友说的
4. **群成员识别** —— 知道「@小a」和正文里打的「小a」是群里的谁，连群头衔一起答
5. **入群欢迎** —— 有人进群，用人设口吻欢迎一句
6. **识图** —— 发图给它，它能看图说话（需模型支持多模态）
7. **联网搜索** —— 带每日额度闸门，闲聊不联网、不花冤枉钱

## 三步上手

```
1. 装 Python 3.10+（安装时勾上「Add Python to PATH」）
2. 双击 启动机器人.lnk（就是解压后文件夹里那个带图标的快捷方式）
3. 在打开的网页里填 QQ 号 / API Key / 人设 → 点「测试连接」→ 点「开始部署」→ 扫码
```

就这三步。剩下的（建虚拟环境、装依赖、下载协议端、写两边配置、拉起服务）启动器全包了。

> 双击 `启动机器人.lnk` 和双击 `启动.bat` 效果完全一样，两个入口都在，习惯哪个用哪个。

**需要准备两样东西**：一个**小号 QQ**（别用主号，原因见第 5 节），一个大模型 **API Key**（第 1 节有申请指引，三家都写了）。

> 想了解每一步到底在干什么、或者不想用启动器，往下看第 2、3 节。

## 架构

```
   QQ 服务器
       ↕  (NTQQ 协议)
   NapCat  ──协议端──  登录你的 QQ 号，把 QQ 协议翻译成 OneBot v11
       ↕  (反向 WebSocket, ws://127.0.0.1:8080/onebot/v11/ws)
   NoneBot2 ──框架──   接收消息、管理上下文、限流、调用模型
       ↕  (OpenAI 兼容 HTTP)
   大模型 API           任意 OpenAI 兼容接口
```

三块各管一件事：**NapCat 让 QQ 号上线，NoneBot2 处理消息，模型负责回答**。三者解耦，任何一块出问题都好单独排查。

**性能要求很低。** 真正的推理在云端，本机只做「收消息 → 拼提示词 → 发 HTTP 请求 → 转发回复」这种轻活：常驻内存约 150–250 MB（NapCat 略高，300 MB 上下），CPU 基本闲置。**2 核 2G 的小机器就够**，甚至树莓派都能跑。唯一吃资源的是 Python 启动时的依赖导入，以及 `get_group_member_list` 这种一次性接口调用。

需要稳定的是**网络**，不是性能：断网 = 机器人掉线。

## 1. 申请大模型 API Key

项目支持任意 **OpenAI 兼容接口**。换厂商只需改 `.env` 里三行（`AI_API_BASE` / `AI_API_KEY` / `AI_MODEL`），**代码零改动**。

### 方案 A：小米 MiMo（实测通过，推荐）

1. 打开 [MiMo API 开放平台](https://platform.xiaomimimo.com/) 注册登录
2. 进 [控制台 → API Keys](https://platform.xiaomimimo.com/#/console/api-keys) 申请
3. 复制形如 `sk-xxxxx` 的 Key

- **Base URL**：`https://api.xiaomimimo.com/v1`
- **模型 ID**：`mimo-v2.6-flash`

> **两种 Key 别混用**：`sk-` 开头是**按量付费**，配 `https://api.xiaomimimo.com/v1`；`tp-` 开头是 **Token Plan 订阅制**，Base URL 以 Token Plan 页面显示的为准，两者相互独立。

可用模型（2026-10 核实）：

| 模型 ID | 输入 / 输出（元 / 百万 token） | 说明 |
|---|---|---|
| `mimo-v2.6-flash` | 1 / 2 | **推荐**，1M 上下文，原生多模态 |
| `mimo-v2.6-pro` | 3 / 6 | 1.02T 参数，能力更强 |
| `mimo-v2.6-pro-ultraspeed` | 30 / 60 | 极速版，价格劝退 |
| `mimo-v2.5` / `mimo-v2.5-pro` | — | **2026-10-21 下线，别选** |

### 方案 B：智谱 GLM（有完全免费的模型）

- **Base URL**：`https://open.bigmodel.cn/api/paas/v4`
- 申请入口：[智谱开放平台](https://open.bigmodel.cn/) → API Keys
- 推荐：`glm-4.5-air`（¥0.8 / ¥2）、`glm-4-flash-250414`（**输入输出全免费**）
- 避坑：`glm-5.3` / `glm-5.3-flash` **强制思考且无法关闭**，不适合群聊

### 方案 C：阿里云百炼

新用户送 7000 万 Token（180 天有效），按群聊机器人的用量能跑很久。

1. 打开 [百炼控制台 → API Key](https://bailian.console.aliyun.com/cn-beijing/model/settings/api-key)
2. 右上角先选**地域**（推荐华北2·北京）。注意：**各地域的域名和 Key 不能混用**
3. 点「创建 API Key」→ 归属账号选主账号 → 权限选「全部」→ 确定

- **Base URL**：`https://dashscope.aliyuncs.com/compatible-mode/v1`

**模型 ID 请以控制台模型列表为准。** 要用的模型（比如 Qwen3.5-Flash、Qwen3.5-Plus）ID 不一样时，改 `AI_MODEL` 即可。

无论选哪家，填完都先验证一下：

- **走启动器** —— 网页里点「测试连接」，它当场真发一条消息，通了才放你继续
- **手动模式** —— 跑一次自带脚本，它直接读 `.env`：

```bash
python check_api.py
```

## 2. 启动：双击就完事了

解压压缩包，双击目录里的 **`启动.bat`**（`start.bat` 是同一个东西，只是文件名全 ASCII，方便在某些环境下调用）。

启动器会自己按顺序做这些事，**你只需要在网页里填一次配置**：

```
双击 启动.bat
   ↓
① 检查 Python，建好独立的虚拟环境（不污染你系统里的 Python）
   ↓
② 打开一个配置网页（本地 127.0.0.1，不联网、不上传任何东西）
   ↓
   你在网页里填：机器人 QQ 号 / 模型厂商 / API Key / 模型 ID / 机器人名字 / 人设
   ↓
③ 先点「测试连接」——当场拿你的 Key 真发一条消息，通了才让你继续
   ↓
④ 点「开始部署」——自动装依赖、自动下载 NapCat 协议端、自动写好两边配置
   ↓
⑤ 浏览器自动打开 NapCat 的扫码页 → 用机器人 QQ 号扫码登录
   ↓
   机器人上线，群里 @它 就能用了
```

配置网页长这样（背景是启动器自带的，不额外占资源）：

| 区域 | 说明 |
|---|---|
| 机器人 QQ 号 | 只用来给 NapCat 做快速登录，填错也能改 |
| 模型厂商 | 预设了 MiMo / 智谱 / 百炼 / 自定义，选完自动填好 Base URL |
| API Key | 粘贴你的 Key。**只写到本机 `.env`，不会发到任何地方** |
| 模型 ID | 填你在厂商控制台看到的实际模型 ID |
| 机器人名字 | 会拼进系统提示词，让模型知道自己叫什么 |
| 人设 | 就是它说话的风格。留空会用一份中性的默认人设 |

页面下方有一块**实时日志**，部署过程中每一步做了什么、卡在哪，都在那里滚动显示，出问题不用去猜。

> **首次运行会下载约 120 MB 的 NapCat 协议端**，视网速需要一两分钟。下载源优先走国内镜像，
> 失败会自动回退到 GitHub 官方。这一步只做一次。

### 关于启动器的图标

你会注意到 `启动.bat` 是那个 Windows 通用的「窗口 + 齿轮」图标——这不是没做，是 **Windows 不允许**：
批处理文件本身没有图标资源，资源管理器永远显示通用图标，任何工具都改不了。

绕这个限制的唯一正规办法是做一个**快捷方式**。压缩包里已经放了一个挂好图标的
**`启动机器人.lnk`**——**解压就能看到，不用先跑一次**：

- 双击 `启动机器人.lnk` 和双击 `启动.bat` 效果完全一样
- 想放桌面，直接把这个快捷方式复制过去就行
- 启动器每次运行还会自动重建它，所以就算把文件夹挪了位置、或者不小心删了它，
  下次启动也会自动恢复，路径跟着更新
- 不想要就删掉，不影响任何功能

### 想改配置怎么办

两种方式，改完重启即可：

- **再跑一次启动器** —— 网页里改完点保存，它会重写 `.env`（不会动 NapCat 那边已经配好的 Token）
- **直接改 `.env`** —— 文件就在项目根目录，每一项都有中文注释。完整参数说明见同目录的 `.env.example`

## 3. 手动部署（不想用启动器时）

启动器只是把下面这些步骤自动化了。如果你在 Linux 服务器上、或者更喜欢自己掌控每一步，可以手动来。

### 3.1 部署 NapCat（让 QQ 号上线）

**Windows**

1. 到 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载 `NapCat.Shell.Windows.OneKey.zip`
2. 解压后双击运行 `NapCatInstaller.exe`，等它自动配置完成
3. 进入生成的 `NapCat.XXXX.Shell` 目录，双击 `napcat.bat` 启动
4. 控制台会打印 WebUI 地址和访问 token，用浏览器打开它

**Linux**

```bash
curl -o napcat.sh \
  https://nclatest.znin.net/NapNeko/NapCat-Installer/main/script/install.sh \
  && bash napcat.sh
```

装完后执行 `napcat` 启动，进入 TUI 界面。

**配置（关键步骤）**

1. 在 NapCat 界面进入 **配置 → 添加新账号**，填入你的机器人 QQ 号
2. 进入该账号的配置页，选择 **反向 WS**
3. 按下面填写：

| 字段 | 填什么 |
|---|---|
| 名称 | 随便，比如 `nonebot` |
| Token | 自己编一串随机字符，**要和 `.env` 里的 `ONEBOT_ACCESS_TOKEN` 完全一致** |
| Url | `ws://127.0.0.1:8080/onebot/v11/ws` |
| 消息格式 | **数组**（务必选这个） |
| 心跳/重连间隔 | 保持默认 |

> **Token 只能用 ASCII 字符**（字母、数字、下划线），**绝对不要写中文**。
> 因为 Token 是放在 HTTP 头里传的，而 HTTP 头不允许非 ASCII 字符。
> 踩过的坑：`.env` 里写成 `ONEBOT_ACCESS_TOKEN=改成你自己的随机字符串` 之后，
> NapCat 连接直接被拒（HTTP 403），排查半天才发现是中文的问题。
> 正确写法示例：`ONEBOT_ACCESS_TOKEN=qbot_xxxxxxxxxxxxxxxx`（十六进制字符，小写）
>
> 启动器会自动生成一串符合要求的 Token 并同步写进两边，所以走启动器就不用操心这条。

> 如果 NoneBot2 和 NapCat 不在同一台机器上，把 `127.0.0.1` 换成 NoneBot2 所在机器的 IP。

4. 回到菜单选 **启动**，选中你的机器人账号
5. 会弹出二维码，**用登录了机器人账号的 QQ 扫码**
6. 账号状态变成「运行中」就成功了

## 4.1 联调验证

**走启动器的话，前两步它已经替你验过了**（它会真的等端口起来才往下走，等不到就报错停下）。
所以第一次用建议还是按顺序过一遍，心里有底：

1. **NoneBot2 起了吗** —— 终端有没有 8080 端口的监听日志
2. **NapCat 连上了吗** —— NapCat 日志里应出现 WebSocket 连接成功的记录；没连上就检查 Token 是否一致、Url 是否写对
3. **机器人能说话吗** —— 群里 @机器人 发 `echo 测试`。这个 `echo` 是内置插件，**不经过大模型**，能回说明链路全通
4. **大模型通吗** —— 群里 @机器人 问「你好」。如果 echo 能回但这步不回，就是 API Key 或模型 ID 的问题

> **一个很常见的假故障**：在群里怎么 @ 都不理你。先看是不是在**私聊**——这个机器人只响应群消息，
> 私聊是设计上就不回的（`on_message` 上挂了 `GroupMessageEvent` 类型过滤）。
> 其次确认确实是 @ 了它（而不是 @ 了别人），以及群里没人把它设成免打扰。

**单独验证 API 是否可用** —— 项目自带一键检测脚本，直接读 `.env`：

```bash
python check_api.py
```

也可以临时指定其他参数，不用改 `.env`：

```bash
python check_api.py --base https://api.deepseek.com/v1 --key sk-xxx --model deepseek-v4-flash
```

脚本会打印模型回复和 token 用量。如果报错，它会直接告诉你原因：

| 报错 | 含义 |
|---|---|
| `401` | Key 不被这个地址认可 —— **多半是 AI_API_BASE 填错了平台** |
| `404` | 模型 ID 不对，或地址少了 `/v1` |
| `429` | 触发限流或余额不足 |

想用 curl 手动测也行：

```bash
curl https://你的接口地址/chat/completions \
  -H "Authorization: Bearer sk-你的Key" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4-flash","messages":[{"role":"user","content":"你好"}]}'
```

- `401` → Key 抄错了或已删除
- `404` / 模型不存在 → `AI_MODEL` 填的 ID 不对，去控制台核对
- `curl` 通了但机器人不回 → 看 NoneBot2 终端日志里的报错

## 4.2 不装 NapCat 也能先跑通：模拟客户端

项目自带 `mock_napcat.py`。它扮演 NapCat 的角色，直接连到机器人的反向 WebSocket 上，
伪造一批群文件和群相册数据，然后把测试消息发进去、把机器人的回复打印出来。

**价值**：还没注册小号、还没装 NapCat、甚至还没决定要不要用 QQ 的时候，
就能先确认「机器人逻辑 + 大模型」这条链路是通的，把问题范围缩小。

用法（两个终端）：

```bash
# 终端 1：启动机器人
python bot.py

# 终端 2：运行模拟客户端
python mock_napcat.py
```

输出长这样：

```
[1/7] 发送：群里有没有团建的照片
  【机器人回复】[引用 1001]有哦～团建照片都在群相册「团建照片」里，张三和李四都传了，一共三张呢～
[3/7] 发送：有没有考勤表
  【机器人回复】[引用 1003]没有，群里没有考勤表哦。
```

**注意**：脚本里的 `TOKEN` 必须和 `.env` 里的 `ONEBOT_ACCESS_TOKEN` 一致，
两条测试消息之间的间隔（`GAP_SECONDS`）必须大于 `.env` 里的 `AI_COOLDOWN`，
否则会被冷却挡掉。测试用的消息列表在 `MESSAGES` 里，随便改。

### 不需要 QQ 也不需要 API 的离线测试

`tests/` 下有四条不花钱的测试，改完代码顺手跑一下很省事：

```bash
python tests/test_websearch.py   # 34 项：额度账本（解析/记账/持久化/跨天/容错）
python tests/test_gate.py        # 70 项：额度闸门 + 关键词触发 + 换模型降级 + 铁律强制附加
python tests/test_members.py     # 71 项：@ 还原 + 名字匹配 + 入群欢迎限流与兜底
python tests/test_comfyui.py     # 181 项：生图（清单解析 / 参数合成 / 工作流 / 落盘 / 假 ComfyUI 全链路）
```

`test_gate.py` 会自己起一个假模型服务器，`test_members.py` 用一个假 Bot 顶替协议端，`test_comfyui.py` 起一个假 ComfyUI，**都不会真的调用 API，也不产生任何费用**。
它们直接跑插件里的真实函数（`_create_completion` / `_build_member_context` / `_system_prompt` / `_image_flow`），所以连配置读取、参数组装、用量扣减、缓存失效都是真实路径。

生图测试另带 `--live` 开关，可连本机真实 ComfyUI 真出一张 512×512 做验证（默认跳过，避免测试依赖外部服务）。

> **这些测试不读你的 `.env`。** 它们会在开头显式钉死自己需要的配置项，测的是代码逻辑而不是你的个人设置。
> 所以你把联网关掉、把人设清空、把欢迎功能禁用，跑测试依然是全绿的——这是刻意的，
> 否则「我改了配置导致测试挂掉」会变成一个莫名其妙的假故障。

> 写测试是有回报的：`test_members.py` 上线就抓出一个真实缺陷——「小a的猫可爱吗」会把「小a」也算成被提到的人（详见 4.7）。
> `test_gate.py` 的第 9 节则守住了「人设怎么写都不能把铁律覆盖掉」这条底线。

## 4.3 关于「思考模式」（重要，直接决定群聊体验）

新版推理模型（GLM 全系、MiMo v2.6 等）在回答前会先输出一大段**思考过程**。这会带来两个麻烦：

1. **回复变慢** —— MiMo v2.6-flash 回答一句闲聊，默认要 **4.6~9.1 秒**；关掉思考后只要 **1.1~2.1 秒**，差 4 倍
2. **正文变空** —— 思考 token 和正文**共用** `AI_MAX_TOKENS` 额度，额度被思考吃光，正文就是空字符串

### 首选做法：直接关掉思考

`.env` 里设 `AI_DISABLE_THINKING=true`，项目会发 `thinking: {"type": "disabled"}`。实测 **GLM 全系与 MiMo v2.6 都认这个字段**，所以换厂商不用改这里。

MiMo v2.6-flash 实测（同一句闲聊）：

| 设置 | 耗时 | 思考 token |
|---|---|---|
| **`AI_DISABLE_THINKING=true`** | **1.1~2.1 秒** | **0** |
| 不传该参数（默认） | 4.6~9.1 秒 | 79~86 |

### 备选做法：调低思考强度

有些模型不允许关闭思考、只能调档，这时用 `AI_REASONING_EFFORT`（low / high / max）。GLM-5.3-Flash 实测（同一个问题）：

| 设置 | 耗时 | 思考 token |
|---|---|---|
| **`AI_REASONING_EFFORT=low`** | **0.9 秒** | **0** |
| 不传该参数 | 6.5 秒 | 202 |
| `AI_REASONING_EFFORT=high` | 14.2 秒 | 674 |

> **`reasoning_effort` 不是万能的。** 实测 **MiMo v2.6-flash 会静默忽略这个参数**——传了不报错，但思考照旧（延迟反而到 10 秒）。要关 MiMo 的思考只能用 `AI_DISABLE_THINKING`。

> GLM-5.3 系列**无法完全关闭思考**（传 `thinking.type=disabled` 会返回 400 报错），只能用 `reasoning_effort` 调档。

**如果你把思考强度调高**（追求更深的推理），务必同步把 `AI_MAX_TOKENS` 从 400 提到 1500 以上，否则正文会被思考过程挤空——代码里检测到空正文时会在日志里提示这一点。

### 怎么判断一个参数是真生效还是被静默忽略

这是排查这类问题最实用的技巧：**先发一个无意义字段（比如 `{"zzz": "x"}`）**。

- 如果它也能返回 200 → 说明服务端对未知字段一律不报错，那么「传了参数但输出没变化」就等于**被静默忽略**
- 真正要看的指标是 `usage.completion_tokens_details.reasoning_tokens` 有没有归零，**不能只看有没有报错**

`check_api.py` 支持 `--no-think` / `--think` 快速切换验证，并会打印耗时与思考 token 数。

## 4.4 群资源检索（核心功能）

群成员问「群里有没有 XX」，机器人会去翻**群文件**和**群相册**，告诉他东西在哪个文件夹、哪个相册。

### 原理：这不是模型能力问题，是工具调用问题

模型**没法自己去翻群文件**。真正干活的是 NapCat 提供的这些 OneBot 接口：

| 接口 | 作用 | 覆盖资源 |
|---|---|---|
| `get_group_root_files` | 列出群文件根目录 | 群文件 |
| `get_group_files_by_folder` | 列出指定文件夹的内容 | 群文件 |
| `get_group_album_list` | 列出群相册 | 群相册 |
| `get_group_album_media_list` | 列出相册里的图片与视频 | 群相册 |

流程是：**递归抓取文件树 + 遍历相册 → 建本地索引（缓存 10 分钟）→ 本地关键词匹配 → 把候选交给模型组织语言。**

这样设计有三个好处：

- **准确** —— 模型只负责措辞，不负责找文件，从根上杜绝编造文件名
- **省钱** —— 匹配在本地做，不耗 token；没有相关内容时根本不调模型
- **快** —— 本地匹配是毫秒级的

> **已知接口限制**（NapCat issue #1670）：协议端单个群最多只能取到 **10 个相册**，单个相册最多 **30 个媒体**。这是 NapCat 自身的限制，不是本项目的问题。资源特别多的群建议提醒成员用群文件而不是相册归档。

### 用法

**方式一：直接命令（推荐，不走模型，秒回）**

```
/files 预算        → 检索名称和位置里含「预算」的资源
/files list        → 列出所有目录与相册及各自数量
/files refresh     → 重建索引（限群主与管理员）
```

**方式二：@机器人 自然提问**

```
@机器人 群里有没有预算表
@机器人 财务那边的表格在哪
@机器人 群里有没有团建的照片
@机器人 有没有年会的视频
```

机器人会依据检索结果回答，找不到就直说没有。

### 检索算法

中文没有空格，「财务那边的表格在哪」整句拿去匹配是匹配不上的。所以算法是反过来的——**找查询里最长的一段、正好出现在文件名、目录名或相册名里**：

| 命中位置 | 权重 |
|---|---|
| 文件名命中，按命中长度 | ×4 |
| 目录名 / 相册名命中，按命中长度 | ×1.5 |
| 空格分词后的整词命中 | +12 |
| 类型相符（问「照片」而它是图片） | ×1.6 |
| 类型不符（问「照片」而它是文档） | ×0.4 |

另外会先剔除「有没有 / 在哪 / 一下 / 群里」这类口水词，避免污染打分。

### 一个踩过的坑：类型加分不能单独制造匹配

加了类型识别后，「有没有量子力学的课件」居然返回了 `产品介绍.pptx`——因为「课件」被识别成类型「演示」，而那个 ppt 确实是「演示」，类型加分让它越过了阈值。**群里根本没有量子力学的东西**，模型拿到这个错误候选就会顺着编。

修法是引入「主体词」概念：把口水词、类型词、虚词全部剥掉后，看还剩不剩东西。

| 提问 | 剥完剩下 | 判定 | 行为 |
|---|---|---|---|
| 有没有压缩包 | （空） | 纯类型查询 | 按类型返回所有压缩包 |
| 有没有量子力学的课件 | 量子力学 | 带主题的查询 | **必须真的匹配上「量子力学」** |

规则改成：**类型只用来重新排序「已经有文本依据」的候选，绝不单独制造匹配。** 宁可回答没有，也不能给模型递错料。

实测效果（12 个样本资源，含群文件与群相册）：

| 提问 | 命中结果 |
|---|---|
| 群里有没有团建的照片 | 团建合影1/2/3.jpg（群相册「团建照片」） |
| 有没有年会的视频 | 年会现场.mp4、产品演示.mp4（群相册「年会视频」） |
| 有没有财务的表格 | 2026年度预算表.xlsx（表格，排第一）、财务报销流程.docx（排第二） |
| 财务那边的表格在哪 | 同上，表格类优先 |
| 有没有压缩包 | 资料汇总.zip |
| 群里有什么图片 | 4 张图片，含群文件与群相册 |
| **有没有量子力学的课件** | **无匹配（正确拒绝，不编造）** |

### 第二个坑：无匹配时，不能把目录清单给模型看

第一次真机跑的时候，问「有没有量子力学的课件」，机器人回答：

> 群文件里没有。根目录、行政、财务那几个文件夹里翻遍了，只有预算表、报销流程、**考勤表**和年会视频……

**「考勤表」是它编出来的**，群里根本没这个文件。

原因是「无匹配」时我把群里的目录和相册清单也一并塞进了上下文，本意是让回答更周到。
但模型看到一份「有什么」的清单，就会顺着往下「推理」出「还应该有什么」——而它对群内容一无所知，
只能靠猜，猜出来的就是幻觉。

修法：**无匹配时只告诉模型「没有」，不提供任何清单。**

```
【群资源检索结果】系统已经检索过该群的群文件与群相册，没有找到任何与你问的东西相关的资源。
回答要求：只回答没有，不要列举群里还有什么别的东西，不要猜测，更不要编造任何文件名或相册名。
```

修完再测「有没有考勤表」「群里有没有关于招聘的文件」，都能干净地答「没有」。

### 第三个坑：OneBot 接口返回数组时被当成空结果丢掉

这个坑更隐蔽——**不报错，功能静默失效**。

现象：问「群里有没有团建的照片」，机器人答「我翻遍了这个群的相册——一个都没有，群相册数量为零」，
但那个群里明明有 2 个相册 5 张照片。

原因：NoneBot 的 `bot.call_api` 已经把响应里的 `data` 字段拆出来返回了，所以返回值
**可能是 dict（对象），也可能是 list（数组）**。`get_group_album_list` 返回的正是数组，
而代码里只放行了 dict：

```python
# 错的：数组会被丢掉，相册功能整个失效
if isinstance(raw, dict) and isinstance(raw.get("data"), dict):
    return raw["data"]
return raw if isinstance(raw, dict) else {}

# 对的：dict 和 list 都要放行
if isinstance(raw, dict) and isinstance(raw.get("data"), (dict, list)):
    return raw["data"]
return raw
```

**教训**：接第三方接口时，「返回结构不符合预期」往往不报错，只是安静地返回空。
所以拿不到数据时要先怀疑解析层，而不是先怀疑接口。

### 第四个坑：模型会把元数据标记原样抄进回复

`describe()` 原本输出的是 `1. [表格] 2026年度预算表.xlsx　位置：群文件「财务」`，
结果机器人回答成了「名为 **[表格]** 2026年度预算表.xlsx」——群成员会看到一串莫名其妙的标记。

修法是**让元数据读起来像人话**，这样即使被逐字照抄也不违和：

```
1. 2026年度预算表.xlsx —— 表格，在群文件「财务」，张三上传，180.0KB
```

配合在回答要求里加一句「用自然口语转述，不要照抄字段名，也不要输出方括号标记」。
修完的回答变成「2026年度预算表.xlsx在群文件的「财务」文件夹里，张三上传的」。

### 修完之后的完整实测（7 个用例，零幻觉）

用 `mock_napcat.py` 走完整链路（真实 NoneBot2 事件管道 + 真实大模型），
模拟数据为：群文件 6 个（分属财务、财务/报销制度、行政、市场、根目录）+ 群相册 2 个共 5 个媒体。

| 提问 | 机器人回答 | 判定 |
|---|---|---|
| 群里有没有团建的照片 | 团建照片都在群相册「团建照片」里，张三和李四都传了，一共三张呢 | ✅ 命中相册 |
| 有没有量子力学的课件 | 没有，群里找不到这类课件～ | ✅ 拒绝 |
| **有没有考勤表** | **没有，群里没有考勤表哦** | ✅ 强诱导，拒绝 |
| 群里有没有关于招聘的文件 | 没有，群里没有关于招聘的文件 | ✅ 拒绝 |
| 财务那边的表格在哪 | 2026年度预算表.xlsx在群文件的「财务」文件夹里，张三上传的 | ✅ 准确 |
| 帮我找一下去年的年终总结PPT | 群文件里没有这样的东西。我列出的资源里只有「产品介绍.pptx」在「市场」文件夹，年会视频倒是有，但去年年终总结PPT是真没有呢 | ✅ 不混淆 |
| 今天好累啊 | 辛苦啦，早点休息～ | ✅ 人设正常 |

### 索引什么时候刷新

- 默认缓存 **10 分钟**（`AI_FILE_INDEX_TTL`）
- 群里刚传了新文件但机器人说找不到，让管理员发 `/files refresh` 立即重建
- 索引存在内存里，重启即丢，下次用到会自动重建

### 想关掉这个功能

```ini
AI_FILE_SEARCH_ENABLED=false
```

## 4.5 人设怎么写

**人设 = 这个机器人说话是什么风格。** 它可以是任何东西：一个毒舌的群友、一个正经的客服、
一个中二的角色扮演，或者干脆没有性格、只求把事说清楚。

两种改法：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **启动器网页**（推荐） | 网页里的「人设」输入框，随便写多行 | 大多数人。会写进 `.env` 的 `AI_SYSTEM_PROMPT` |
| **改代码** | 改 `plugins/ai_chat/config.py` 里的 `ai_system_prompt` | 想把默认人设固化下来、分发给别人 |

> 优先级：`.env` 里的 `AI_SYSTEM_PROMPT` 覆盖 `config.py` 里的 `ai_system_prompt`。
> 所以网页填过之后，改 `config.py` 是不会生效的——要改就改 `.env`，或者把网页里的人设清空。

### 设计上的关键取舍：人设不能干扰事实

系统提示词是四段拼起来的，**顺序很重要**：

```
今天的日期是 ……              ← 代码强制，让你问「今天天气」不会算错日子
你的名字是「……」              ← 代码强制，来自网页里填的机器人名字
【性格】【说话方式】……        ← 你写的人设，只管语气
【铁律 —— 优先级高于上面所有性格设定】   ← 代码强制，管事实
```

**注意最后一段不是你写的，是代码加的。** 它叫 `IRON_RULES`，在 `plugins/ai_chat/__init__.py` 里，
由 `_system_prompt()` 无条件附加——不管你人设怎么写、写在哪（网页 / `.env` / `config.py`），它都跑不掉。

> **为什么要这么设计**：早先这几条是写在默认人设正文里的，结果只要用户在网页上填了自己的性格，
> 整段约束就被一起覆盖掉了，机器人开始在群里报不存在的文件名。
> 把它从人设里拆出来、放进代码，这个缺口就堵上了。

铁律有七条，核心是前五条：

1. 系统给出「群资源检索结果」时，必须严格依据那份列表回答，**列表里没有的一律说没有**，禁止编造文件名、相册名或链接
2. 「群精华消息检索结果」同理，且要说清是哪位群友说的
3. 对方发来图片时，只描述真正看到的内容，看不清就说看不清
4. 「群成员识别结果」里没有的（他们说过什么、做过什么），一律说不知道
5. **人设只影响语气，不影响事实。** 哪怕语气再随意，说出来的文件名和位置也必须准确

为什么要把这几句写死：人设越浓，模型越容易「入戏」到自由发挥。而群文件检索是**事实型任务**，一句编造的文件名就会让整个功能失去信任。把约束放在人设之后、并明确声明优先级，实测下来语气能立住、事实也不跑偏。

另外两条是：不用 Markdown（QQ 不渲染）、违法有害请求直接拒绝且不用人设包装。

### 实测效果

| 场景 | 回答 |
|---|---|
| 群文件命中 | 在财务文件夹里，有2026年度预算表.xlsx，上传者是张三 |
| 未命中 | 没有哦，群文件里没有量子力学的课件 |
| **诱导编造**「找一下去年的年终总结PPT」 | **没找到，群文件里没有年终总结相关的PPT** ✅ 不编造 |

### 想改语气浓度

**放心改，改坏不了。** 人设里只写性格和说话方式就行，防幻觉的底线由代码兜着，你写成什么样它都还在。

想加口癖、加语气词、甚至彻底换成另一个角色的说话方式，都没问题。

> 唯一的例外是第 6 条「不用 Markdown」——如果你的人设里明确要求输出 Markdown，
> 那两条指令会打架。QQ 不渲染 Markdown，所以还是别那么写。

## 4.6 联网搜索（可选，带每日额度闸门）

联网让机器人能回答「今天天气」「最新股价」这类需要实时信息的问题。默认**是关闭的**——因为大多数厂商的联网是单独的付费服务插件，要先在控制台开通才能用；没开通时程序会自动降级成普通对话，不会报错，但你也不会真的联上网。

开通之后把 `AI_WEB_SEARCH_ENABLED` 改成 `true`，并设一个每日上限（默认 30 次）。

### 为什么必须设额度

MiMo 的联网能力是「服务插件」，**按插件调用次数计费**（¥16 / 1000 次），而且一轮搜索会按 `max_keyword` 的数值**同时并发**搜多个关键词——一次提问可能消耗好几次调用。再叠加网页正文拼进提示词带来的输入 token 费用（实测一次联网提问的 prompt_tokens 从几十涨到 1390 左右）。

群聊是高频场景，不设闸门很容易跑飞，所以做了两层控制：

```
AI_WEB_SEARCH_ENABLED=true
AI_WEB_SEARCH_FORCE=false        ← 保持 false，让模型自己判断要不要联网
AI_WEB_SEARCH_MAX_KEYWORD=2      ← 单轮成本旋钮，调到 1 最省
AI_WEB_SEARCH_DAILY_LIMIT=30     ← 全局每天上限（所有群加起来算）
```

### 额度是怎么算的

**不是估算，是读官方返回的真实计费次数。** 响应体里带：

```json
"usage": {
  "prompt_tokens": 1390,
  "web_search_usage": { "tool_usage": 2, "page_usage": 2 }
}
```

`tool_usage` 就是这一轮实际计费的插件调用次数，代码直接拿它扣额度。**模型判断这个问题不需要联网时它是 0，不扣额度**——所以闲聊不会浪费配额，只有真的搜了才计数。

⚠️ 实现上有个坑：`web_search_usage` 在 SDK 返回的对象里是**普通 dict**，不是 pydantic 子对象。用 `getattr(usage, "web_search_usage")` 能取到，但再往下 `getattr(obj, "tool_usage")` 会返回 `None`。必须按 dict 取。写错了计数就永远是 0，额度形同虚设。

额度用尽后自动摘掉 `tools` 参数——**不挂 tools 就不会产生联网费用**，对话照常进行，只是回答基于模型已有知识。次日零点自动恢复。

> 边界说明：额度检查发生在请求之前，而一轮搜索最多消耗 `max_keyword` 次，所以最后可能小幅超出（例如剩 1 次时搜了 2 次，记 31/30）。这是刻意取舍——预留额度会白白浪费配额，而超出的上限只有 `max_keyword` 次，成本可忽略。

### 额度是持久化的

存在 `data/web_search_usage.json`，**重启不清零**。这点很重要：只存内存的话，每次改配置重启都会把当天用量抹掉，额度等于没有。跨天自动归零。

### 查看用量

在群里发 `/联网`（或 `/search`）：

```
联网搜索额度（2026-10-11）
　已用 6 / 30 次
　剩余 24 次
　实际触发联网的回答 4 条
　触发方式：命中时效性关键词才联网
　每轮最多 2 个关键词（由模型自行判断是否需要联网）
　注：计费单位是插件调用次数，一轮搜索若用 2 个关键词就计 2 次
```

群主或管理员可以发 `/search reset` 手动重置当天额度。

### 为什么不是每条消息都挂着联网参数

实测：**即使模型最终没联网，只要请求里挂了 `tools`，服务端就会多做一轮「要不要联网」的判断，每条消息白慢约 1.2 秒**（1.68s → 2.86s）。

所以做了关键词闸门，只有消息里出现时效性词（今天 / 最新 / 天气 / 股价 / 搜一下 ……）才挂联网参数：

```
AI_WEB_SEARCH_TRIGGER=auto     ← 默认，按关键词触发
AI_WEB_SEARCH_TRIGGER=always   ← 每条消息都挂（慢 1.2s，但永远不会漏）
```

关键词表在 `plugins/ai_chat/websearch.py` 的 `WEB_SEARCH_KEYWORDS`，想加词直接往那个元组里塞。

### 容错

**即使哪天插件失效也不会出事**：代码识别到 `webSearchEnabled` 这个报错后会自动降级成普通对话，只在日志里留一条警告，**并且这次不扣额度**。这是刻意做的容错。

### 另一个坑

MiMo 的联网开关有 **5 分钟缓存**：改完配置的 5 分钟内，开关可能还没真正生效。别改完就急着测，会误判。

## 4.7 群成员识别（@ 与名字）

让机器人明白「@小a 他怎么样」和「小a怎么样」说的都是群里的那个小a。

### 根因：@ 在模型眼里是隐形的

`event.get_plaintext()` **只取 `text` 消息段，`at` 段被整个丢掉**。所以：

```
群里实际发的：  @机器人 @小a 他最近怎么样
get_plaintext： 他最近怎么样
```

到模型眼里，「他」没有任何指代对象，只能瞎猜或者反问「小a是谁」。

所以不再用 `get_plaintext()`，改成自己遍历消息段重建文本（`members.render_text`）：

- `text` 段 → 原样保留
- `at` 段（其他人）→ 还原成 `@小a `，名字后补空格避免黏成「@小a他最近」
- `at` 段（机器人自己）→ 去掉，那是触发用的，不算内容
- `at` 段（`all`）→ 还原成 `@全体成员 `

### 第二种情况：直接打名字

「小a怎么样」里的「小a」在模型眼里只是两个普通汉字。这类靠**本地成员名单**做匹配解决：拉一次 `get_group_member_list` 建索引（带 TTL 缓存），在消息正文里找成员名。

**只有命中的成员才拼进提示词。** 一个群几百人，全塞进去 token 直接爆，而且模型看到一长串无关名单反而更容易张冠李戴。

### 名字匹配的两个细节

**一、单字昵称不参与匹配。** 叫「鱼」「A」这种，一句话里到处都是，误伤率太高。宁可认不出来，也不要乱认人——所以 `MIN_NAME_LEN = 2`。

**二、长名字优先，但要判「有没有独立出现」。**

「小a」和「小a的猫」同时是群成员时，说「小a的猫可爱吗」应该只认出「小a的猫」。

最初的实现是「按命中名字长度排序，长的排前面」——听起来对，其实不够：它仍然把两个人都塞给了模型。**这是写测试时才发现的问题**，现在改成检查出现位置是否重叠：

```
小a的猫可爱吗        → 只有「小a的猫」（「小a」只是它的一部分）
小a和小a的猫都来了   → 两个人都在（两处都独立出现了）
```

### 给模型的资料带防幻觉约束

```
【群成员识别结果】对方这条消息里提到了以下群成员，系统已从群名单里查到他们的真实资料：
- 「小a」（群名片：小a｜昵称：咸鱼｜QQ：1001｜群身份：群主｜群等级：9｜专属头衔：摸鱼冠军）
回答要求：……至于他们说过什么、做过什么、和谁关系好，上面没有的就说不知道，别自己想象。
```

最后一句很关键：名单里**只有身份信息，没有聊天记录**。不写这句，模型会顺着「他是群主」编出一堆「他经常组织活动」之类的事。

### 用法

```
@机器人 @小a 他最近怎么样     ← @ 的人会被认出来
@机器人 小a是管理员吗         ← 正文里打名字也能认出来
/成员 小a                    ← 按名字或 QQ 号查群成员
/成员 refresh                ← 重建成员名单（限群主与管理员）
```

### 配置

```
AI_MEMBER_ENABLED=true
AI_MEMBER_INDEX_TTL=1800     ← 名单缓存 30 分钟；代价是新人入群后最多这么久内认不出来
AI_MEMBER_MAX_RESULTS=5      ← 一条消息最多给模型几个成员的资料
```

> 有人入群时欢迎功能会自动 `invalidate` 掉该群的名单缓存，所以新人通常不会被这个 TTL 卡住。

## 4.8 新成员入群欢迎

有人入群时，按你设定的人设欢迎一句，比如「欢迎 小a 进群～有什么想问的直接 @ 我就行。」

### 这是「主动发消息」，风险要单独说

其他所有功能都只在**被 @ 时**才说话。入群欢迎是机器人自己开口——而「短时间内连发多条消息」正是 QQ 风控最敏感的行为。所以限流比聊天更严：

```
AI_WELCOME_ENABLED=true
AI_WELCOME_COOLDOWN=15       ← 同群两次欢迎的最小间隔（秒）
AI_WELCOME_DAILY_LIMIT=20    ← 每群每天最多欢迎几次
```

有人一次拉一群人进群时，只会欢迎第一个，后面的直接跳过（日志里留一条 `跳过入群欢迎`）。

**真觉得有风险就把 `AI_WELCOME_ENABLED` 改成 `false`。**

### 生成方式：模型 + 模板兜底

欢迎语由模型生成（写死的几句话第二天就腻了），但**模型挂了、没配 Key、超时都会自动退回写死的模板**，不会因为生成失败就沉默：

```
欢迎 {name} 进群～有什么想问的直接 @ 我就行。
{name} 来了，欢迎欢迎。
欢迎 {name}，记得先看一眼群规。
{name} 进群啦，大家欢迎一下。
```

这四句刻意写得中性、不绑定任何人设——你改成人设后它们依然说得出口。

只取模型返回的**第一行**：它偶尔会写成小作文或带列表符号，群里刷屏很难看。

### 查状态

```
/欢迎
```

```
入群欢迎（2026-10-11）
　状态：开启（AI_WELCOME_ENABLED）
　本群今日已欢迎 2 / 20 次
　同群冷却：15 秒
```

### 一个实现细节

入群通知到达时，新成员的信息在协议端**可能还没建好**，第一次查 `get_group_member_info` 经常返回空。所以查名字带了重试（3 次，间隔 0.6 秒）；彻底查不到就退回 QQ 号——宁可叫号码，也别不吭声或者报错。

## 4.9 表情包（可选）

把图片丢进 `stickers/` 目录就能用，支持 jpg / png / gif / webp。

```
AI_STICKER_ENABLED=true
AI_STICKER_PROBABILITY=0     ← 0 = 只在别人明确索要时才发
```

两种触发方式：

| 方式 | 触发条件 | 说明 |
|---|---|---|
| 明确索要 | 说「表情包」「发个表情」「来张图」「斗图」等 | 必定发一张 |
| 随机附带 | `AI_STICKER_PROBABILITY` 概率命中 | 例如设 0.15 ≈ 每 7 次回复附带 1 次 |

**建议 `AI_STICKER_PROBABILITY` 保持 0。** 群里每句话都带张图，几天就会被嫌烦。

目录里现在只有一份说明文件，**图片数量为 0 时功能会静默失效**（不会报错，只是不发图）。建议放 20 张以上，不然重复率太高。

实现上用的是本地目录而不是在线图库：不需要额外依赖，不怕图库挂掉或限流，也不会把群里的聊天内容发到第三方。

> 发送时用的是 `file://` URI 而不是裸 Windows 路径——CQ 码里反斜杠是转义符，直接传 `C:\xxx\a.jpg` 会解析出错。

## 4.10 本地生图（可选：接本机 ComfyUI）

群友发 `/画 一只在雨里的猫`，机器人把提示词送进**你本机的 ComfyUI**，出图后直接发回群里。全程不出本机、不调云端 API。

**默认关闭**——生图吃显存、属于「被叫到就主动发图」，风控风险比纯文本高。想用三步：

1. 本机启动 ComfyUI（默认 `127.0.0.1:8188`），`models/checkpoints/` 里放好模型
2. `.env` 里把 `AI_IMAGE_ENABLED` 改成 `true`，重启机器人（其余 22 项 `AI_IMAGE_*` 参数见 `.env.example` 与 `plugins/ai_chat/config.py` 的注释）
3. 群里发 `/画 提示词`，可跟参数：`--尺寸 768x768 --步数 30 --cfg 7.5 --模型 名字 --采样器 dpmpp_2m --种子 123 --数量 2 -n 负向词`

| 命令 | 作用 |
|---|---|
| `/画 提示词` | 生成一张图（别名：画画 / 绘图 / 文生图 / draw / 生成图片） |
| `/画图模型` | 列出本机 ComfyUI **真实支持**的模型 / LoRA / 采样器 / 调度器 / VAE / ControlNet |
| `/comfy` | 生图状态：在不在线、显卡、队列、本群今日额度 |

几个要点：

- **清单不是猜的**：`/画图模型` 读的是 ComfyUI 的 `/object_info`，列出来的就是本机真能跑的。刚放了新模型，群主/管理员发 `/画图模型 refresh` 刷新。
- **不需要先在 ComfyUI 里搭工作流**：插件用内置文生图节点现场拼工作流提交，不依赖任何自定义节点。
- **模型名支持模糊匹配**：写 `dreamshaper` 就能命中 `DreamShaper_8_pruned.safetensors`；写错的模型/采样器会自动退回可用值并在回执里说明，不会静默替换。
- **防呆**：宽高自动对齐 8 的倍数并夹在 `AI_IMAGE_MAX_WIDTH/HEIGHT`（默认 1024）之内；同一条命令 + 同一个种子可复现同一张图。
- **限流独立于聊天**：同群冷却默认 30 秒、每群每日默认 20 张，在提交前扣减、失败不退回，避免连点绕开。
- 启动器重写 `.env` 时会**原样保留**已配好的生图参数。

实测（RTX 5060 8GB）：512×512 / 8 步约 2~5 秒出图；本机读回 1805 个节点定义、6 个检查点、69 个 LoRA、45 个采样器。

## 5. 防封号策略（务必读）

第三方协议端绕过了官方接口，QQ 对自动化行为的检测是真实存在的。项目里已经做了基础防护，你还需要注意：

**代码里已经做了的：**

- 只在被 **@** 时才响应，不会主动插话
- 每群 **5 秒冷却**（`AI_COOLDOWN`），防刷屏
- 每群 **每日 200 次上限**（`AI_DAILY_LIMIT`），防账单失控
- 单次输出限制 400 token（`AI_MAX_TOKENS`）

**你必须自己注意的：**

| 高危行为 | 建议 |
|---|---|
| 用主号跑机器人 | **换小号**。这是最重要的一条 |
| 私聊陌生人 / 主动加好友 | 完全不要做 |
| 短时间内大量发消息 | 把 `AI_COOLDOWN` 调到 10 秒以上 |
| 群数量太多 | 用 `AI_GROUP_WHITELIST` 限制在几个自己的群里 |
| 机器人发链接 | 大模型有时会输出 URL，可在 `config.py` 的 `ai_system_prompt` 里明确禁止 |
| 小号刚注册就上机器人 | 先正常养几天号 |

如果账号被限制，通常表现为消息发不出去。**立刻停掉机器人**，用手机正常登录养一段时间。

> 如果你要做的是长期、正式的产品，请走 [QQ 机器人开放平台](https://q.qq.com) 官方渠道，合规且没有封号风险，代价是需要开发者认证和审核，功能也受官方 API 限制。

## 6. 让它 7×24 运行

NapCat 和 NoneBot2 都要常驻。

**Linux（systemd）** —— 在 `/etc/systemd/system/qqbot.service` 写入：

```ini
[Unit]
Description=QQ AI Bot (NoneBot2)
After=network.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/qq-ai-bot
ExecStart=/opt/qq-ai-bot/.venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now qqbot
sudo systemctl status qqbot
```

NapCat 同样用 systemd 托管（安装脚本一般会帮你生成，用 `systemctl list-units | grep napcat` 查一下）。

**Windows** —— 用「任务计划程序」创建两个任务，分别开机启动 `napcat.bat` 和 `python bot.py`，都勾选「不管用户是否登录都要运行」。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `启动.bat` 的图标改不了 | Windows 不允许批处理文件带自定义图标，这是系统限制。用文件夹里的 `启动机器人.lnk`，那个是有图标的（解压即有，无需先运行） |
| 快捷方式双击没反应 / 图标是白的 | 把文件夹挪过位置的话，旧的快捷方式会失效。重新跑一次 `启动.bat`，它会自动重建 |
| 想把带图标的启动方式放桌面 | 把文件夹里的 `启动机器人.lnk` 复制到桌面即可 |
| 双击 `启动.bat` 一闪就没了 | 没装 Python，或装的时候没勾「Add Python to PATH」。命令行里 `python --version` 能出版本号才算装好 |
| 启动器说找不到 Python | 同上。装好后**重开**一次命令行窗口（PATH 要新窗口才生效） |
| 卡在「下载协议端」很久 | 首次要下约 120 MB。它会先试国内镜像、失败再回退 GitHub，网慢就耐心等；实在下不动看下一条 |
| 下载协议端失败 | 手动去 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载后解压到项目根目录，再重跑启动器（见第 3.1 节） |
| 配置网页打不开 | 换个端口重试：命令行跑 `launcher.py --web-port 8900`。端口被别的程序占了会这样 |
| 填完点「测试连接」报 401 | Key 和厂商不匹配。最常见的错是拿 A 家的 Key 配了 B 家的 Base URL |
| 填完点「测试连接」报 404 | 模型 ID 不对，或 Base URL 少了 `/v1` |
| 网页上的按钮点了没反应 | 看页面下方那块实时日志，它会写清楚卡在哪一步 |
| 想换回命令行模式 | `launcher.py --cli`，就是不带图形界面的老式交互 |
| 只想检查环境不想真启动 | `launcher.py --check-only` |
| NapCat 连不上 NoneBot2 | Token 不一致；或 Url 写错；或 NoneBot2 没启动 |
| NapCat 连上被拒（HTTP 403） | **Token 里有中文**。HTTP 头不允许非 ASCII 字符，改成字母数字下划线 |
| 连本机 8080 却报 502 Bad Gateway | 机器上开着代理（`HTTP_PROXY`）。本机回环地址不该走代理，设置 `NO_PROXY=127.0.0.1,localhost` 后重启 |
| `pip install` 报 `from versions: none` | 当前 Python 的 pip 坏了。换一个 Python 解释器建虚拟环境：`<另一个python> -m venv .venv`，再用 `.venv\Scripts\pip install -r requirements.txt` |
| echo 能回，AI 不回 | `AI_API_KEY` 或 `AI_MODEL` 不对，看 NoneBot2 日志 |
| 扫码登录后立刻掉线 | 换小号；或该账号已被风控 |
| 回复很慢 | 确认 `AI_DISABLE_THINKING=true`；仍慢可换模型，或把 `AI_HISTORY_ROUNDS` 从 8 降到 4 |
| 日志出现 `webSearchEnabled is false` | 联网插件没开通或失效，程序已自动降级且不扣额度。去控制台开通即可，或把 `AI_WEB_SEARCH_ENABLED` 改成 false 消除告警 |
| 日志出现「今日联网额度已用尽」 | 当天 30 次用完了，次日零点自动恢复。发 `/search` 看用量，管理员可 `/search reset` 重置 |
| 额度好像不扣 / 一直是 0 | 只有模型真正触发搜索才计数。闲聊不联网就是 0 次，属正常 |
| 问「群里有没有 XX」总是说没有 | 先发 `/files list` 看索引里到底有没有东西；相册类资源受 NapCat 限制（单群最多 10 个相册） |
| 群相册里明明有照片却说没有 | 检查 NapCat 版本是否支持 `get_group_album_list`；看 NoneBot2 日志里有没有「读取相册失败」 |
| 发了表情包但机器人没反应 | `stickers/` 目录里没图片。空目录时功能静默失效，不会报错 |
| 机器人答非所问 / 忘了上下文 | 上下文是内存存储，重启即丢，属正常 |
| 想清空某个群的上下文 | 群主或管理员在群里发 `/reset` |
| 只想让特定群能用 | `AI_GROUP_WHITELIST=[群号1, 群号2]` |
| QQ 不渲染 Markdown | 已在系统提示词里禁止输出 Markdown，如仍出现可加强措辞 |
| 觉得人设不够味 / 太中二 | 在启动器网页里改人设，或改 `.env` 的 `AI_SYSTEM_PROMPT`。防幻觉的铁律由代码强制附加，改人设不会把它弄丢 |
| 机器人编造了不存在的文件名 | 先发 `/files list` 确认索引里到底有没有。确实不存在却说了有，那是模型没守住铁律——铁律在 `plugins/ai_chat/__init__.py` 的 `IRON_RULES` 里，不在 `.env` |

### 扫码登录报「账号近期存在安全风险」（serverErrorCode 168）

**这不是 NapCat 或本项目的问题，是腾讯把这个 QQ 号风控了。** 原始报错：

```
[Login] Login Error, ErrInfo: [1,{"account":"...","serverErrorCode":168,
"message":"你的账号近期存在安全风险，部分功能使用受限，请登录最新手机QQ并根据提示恢复账号使用。"}]
```

典型过程是：正常登录 → 用了几十分钟到几小时 → 被 `[KickedOffLine]` 踢下线
（日志原文：`[下线通知] 你的账号当前登录已失效，请重新登录。`）→ 再扫码就被拒。

处理办法：

1. **用手机 QQ 登录这个号**，按 App 里的提示走完验证流程（可能要改密码、短信验证、
   确认设备）。腾讯的报错里已经写明了唯一途径就是「登录最新手机QQ并根据提示恢复」，
   绕不过去。
2. 去 [QQ 安全中心](https://aq.qq.com) 查看账号状态和近期登录记录。
3. **在账号恢复正常之前，不要反复扫码。** 每次失败都是一次异常登录尝试，
   可能让风控更严。
4. 解除通常需要**几小时到一两天**，期间耐心等，别折腾。

这是第三方协议端的固有风险，不是配置错误。已知较新版本的 NapCat + QQ 组合更容易
触发（参考 [NapCatQQ issue #1728](https://github.com/NapNeko/NapCatQQ/issues/1728)），
社区的缓解手段是降级 NapCat / QQ 版本，或改用 Launcher 方式部署并开启反检测，
但都只是缓解，不是根治。**所以务必用小号，别用主号。**

判断是不是这个原因，看 `NapCat/napcat_run.log` 里有没有 `serverErrorCode` 或
`KickedOffLine` 关键字即可，和本项目代码无关。

## 8. 成本参考

**先看实测的单次消耗**（MiMo v2.6-flash，关掉思考，含完整系统提示词）：

| 场景 | 输入 token | 输出 token | 单次成本 |
|---|---|---|---|
| 群文件检索（带索引上下文） | 285 | 23 | ≈ ¥0.00033 |
| 纯闲聊 | 123 | 22 | ≈ ¥0.00017 |
| 联网搜索（实测，搜了 2 个关键词） | 1390 | 72 | ≈ ¥0.034 |

注意最后一行，它比其他场景**贵两个数量级**。拆开看：token 只占 ¥0.0015，剩下 **¥0.032 全是联网插件费**（2 次调用 × ¥0.016）。同时输入 token 也从一百多涨到 1390——网页正文被拼进了提示词。所以联网的真实成本是「插件费 + 多出来的 token 费」，且**插件费占绝对大头**。

按 `AI_WEB_SEARCH_DAILY_LIMIT=30`（全局）算：30 次插件调用 ≈ ¥0.48，加上 token 约 ¥0.02，**每天上限约 ¥0.5，一个月约 ¥15**。这个上限是硬的，不会因为群里刷屏而突破。

按每个群每天 400 次调用、输入随历史累积到约 600 token 估算：

| 模型 | 单个活跃群月成本 |
|---|---|
| **MiMo v2.6-flash** | **约 ¥4 ~ 10** |
| GLM-4.5-Air | 约 ¥3 ~ 8 |
| GLM-4-Flash-250414 | **¥0（完全免费）** |
| MiMo v2.6-pro | 约 ¥15 ~ 30 |
| 本机 Ollama 跑 Qwen3.5-9B | 只有电费 |

**关键结论：这个量级下各家差价只有几块钱，选型不该只看价格。** 真正影响体验的是**延迟**（群里没人愿意等 5 秒）和**有没有免费兜底档**。

建议**给机器人单独建一个 API Key**，方便在控制台单独看它的消耗，花超了直接停用，不影响你其他项目。

另外注意：`AI_HISTORY_ROUNDS=8` 是刻意压低的。上下文越长，输入 token 线性增长，费用也跟着涨——这个参数每加 1，单次成本大约多 5%。

## 9. 想换成你本机跑的模型？

先说结论：**这个机器人的场景，本地模型目前不划算。** 原因不是跑不动，是三个硬伤：

| | 云端 API（现在的 MiMo） | 本机跑 |
|---|---|---|
| 回复延迟 | **1.1 ~ 2.1 秒** | 3 ~ 6 秒（4B / 9B） |
| **联网搜索** | 有（服务插件） | **没有**。那是厂商的私有服务，本地模型拿不到 |
| 7×24 稳定性 | 云端，跟你机器无关 | 机器一睡 / 一重启就掉线 |

而省下的钱少得可以忽略：一条普通消息约 ¥0.0002，一天 200 条约 ¥0.04，**一个月一块多**。为省一块多去换 3 倍延迟 + 丢掉联网能力，不值。

### 那什么时候值得本地跑？

- 想让群里**能识图但不花钱**，且能接受慢一点
- 群消息量很大（比如一天上千条），或者想开 `AI_WEB_SEARCH_TRIGGER=always`
- 就是**想玩玩**，或者有数据不出本机的需求

### 推荐哪个模型

按「回一条 100 token 的消息要等多久」算（数字来自 M5 实测 TPS + 首字延迟）：

| 模型 | 量化后体积 | 12GB 显存 PC | MacBook Air M5 | 备注 |
|---|---|---|---|---|
| **Qwen3.5-9B** | 6.6 GB | **✓ 首选** | 勉强（≈5.5s） | 综合能力最强，MMLU-Pro 82.5 |
| **Qwen3.5-4B** | 3.4 GB | ✓ 很快 | **✓ Mac 首选**（≈3.3s） | 小模型之王，MMLU-Pro 79.1 |
| Gemma4-26B-A4B | ~15 GB | ✗ | ✓ 24G 起（≈3.0s） | MoE 激活 4B，速度出乎意料 |
| ERNIE-4.5-21B-A3B | ~13 GB | ✗ | ✓ 24G 起（≈2.7s） | MoE 激活 3B，最快 |
| Qwen3.5-0.8B | 1.0 GB | ✓ | ✓ | 极限轻量，只能应付简单问答 |
| Qwen3.6-27B | 17 GB | ✗ | ✗（≈17.7s，不可用） | 太大，别碰 |

**MoE 是这里的关键**：像 `A3B`（总参 21B、每次只激活 3B）这类模型，显存占用按总参数算，但速度按激活参数算——所以在内存受限的机器上，它比同体积的稠密模型快好几倍。这是 2026 年本地部署最值得利用的一点。

**注意**：上表的 TPS 是「短输入」实测。机器人真实请求里带了人设 + 铁律 + 检索结果，prompt 常有一两千 token，首字延迟会明显更长。所以实际体验比表里更慢。

### 怎么跑

```bash
# 12GB 显存的 PC（综合最强）
ollama pull qwen3.5:9b

# MacBook Air（内存吃紧，要速度）
ollama pull qwen3.5:4b

ollama serve
```

然后改 `.env`：

```ini
AI_API_BASE=http://127.0.0.1:11434/v1
AI_API_KEY=ollama
AI_MODEL=qwen3.5:9b
```

代码一行都不用动 —— 因为 Ollama 也是 OpenAI 兼容接口。

### 两个必须知道的限制

1. **联网搜索会失效**。`web_search` 是厂商的私有服务端工具，本地引擎不认识它。
   代码会识别这类报错并**自动摘掉 tools 重试**（见 `_web_search_unavailable`），
   所以不会崩、不会白扣额度，只是这一轮没联网。但日志里会留警告，建议直接把
   `AI_WEB_SEARCH_ENABLED` 改成 `false` 更干净。
2. **识图能力取决于模型**。Qwen3.5 / Qwen3.6 / Gemma4 全系原生多模态，可以；但纯文本模型（如 Phi-4-mini）必须把 `AI_VISION_ENABLED` 改成 `false`，否则收到图会 400。

### 切换前建议先量一下

本机跑之前，先用 `check_api.py` 确认接口通、延迟能接受：

```bash
python check_api.py
```

它会打印实际耗时。**群里没人愿意等 5 秒**——如果实测下来一条消息要 6 秒，就说明这台机器不适合当机器人的后端，还是留着云端 API 更好。

### 一个更划算的组合

**Mac 负责挂机器人，模型留在云端。** 机器人本体只吃 150~250 MB 内存、CPU 基本闲置，Mac 的低功耗正好适合 7×24；而推理这种重活交给云端，延迟还低。两件事不必绑在一起。

> 注意：如果机器人跑在云服务器上，而模型跑在你家里的电脑上，需要用 frp 之类的内网穿透把 Ollama 端口暴露出去。这种情况下反而不如直接用 API 省事。
